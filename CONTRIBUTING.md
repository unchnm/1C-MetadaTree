# Правила разработки 1C-MetadataTree

Проект основан на `upstream/main` репозитория `lekot/VScodePluginFor1CDev`.

- `origin` — `unchnm/1C-MetadataTree`.
- `upstream` — оригинальный CDT 41.
- `main` — проверенная версия проекта.
- `feature/<name>` — отдельная новая функция.
- `fix/<name>` — исправление.
- `sync/upstream-<date>` — обновление из оригинала.

Перед работой проверять ветку и незакоммиченные изменения:

```bash
git status --short --branch
git remote -v
```

## Разработка

1. Работать в отдельной ветке.
2. По возможности выносить нашу логику в отдельные файлы.
3. Если меняется файл оригинала, ограничивать изменение коротким блоком или точкой подключения.
4. Помечать наши участки парными комментариями:

```ts
// 1C-MetadataTree: begin <назначение блока>
// код форка
// 1C-MetadataTree: end <назначение блока>
```

Для HTML/Webview использовать `<!-- 1C-MetadataTree: begin ... -->` и `<!-- 1C-MetadataTree: end ... -->`, для CSS — `/* ... */`. В JSON комментарии невозможны, поэтому изменение фиксировать отдельным тематическим коммитом и описывать в этом файле.

5. Один коммит должен содержать одну связанную доработку.
6. После изменения запускать относящиеся к нему тесты и сборку.
7. Не коммитить `node_modules`, временные файлы и лишние VSIX.
8. Не выполнять `git push --force` без отдельного решения.

## Обновление оригинала

```bash
git switch main
git pull --ff-only origin main
git fetch upstream
git switch -c sync/upstream-YYYY-MM-DD
git merge --no-ff upstream/main
npm run compile
npm run test:ci
npm run package
```

Конфликты разрешать в отмеченных блоках, сохраняя необходимое поведение обеих сторон. После разрешения проверить, что парные маркеры остались на месте.

## Правила для автоматического помощника

Помощник обязан сначала проверить состояние Git, прочитать этот файл и найти существующую точку подключения. Он не должен переписывать опубликованную историю, удалять чужие незакоммиченные файлы, добавлять внешние рантаймы без обоснования или сообщать о пройденной проверке без её запуска.

В финальном сообщении указывать изменённые файлы, коммит, ветку, выполненные проверки и ограничения проверки.

## Текущие согласованные доработки

В форке сохраняются только:

- собственные идентификаторы `1c-metadata-tree` и `unchnm.1c-metadata-tree`;
- временная строка поиска, лупа, крестик, поиск при вводе и сохранение запроса;
- открытие модулей объекта, менеджера и формы с их расположением в меню;
- открытие модуля основной формы объекта;
- отдельное копирование имени и пути;
- исправление `Ctrl+Alt+T` для модулей форм;
- исправление плюса в разделе «Поля» конструктора запросов;
- стандартные иконки оригинального CDT 41.

Поиск по синонимам, история поиска, фоновые индексы, иконки Platform Tools, группировка документов и прототип свойств в рабочую ветку не входят.
